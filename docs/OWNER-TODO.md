# Что требует владельца

Сборка работает без этого, но для публичной раздачи нужно:

## 1. Подпись кода
- **Windows.** `TKBK IDE.exe`, `TKBK-IDE-Setup-*.exe` не подписаны → SmartScreen предупреждает при
  первом запуске. Нужен сертификат code signing (OV/EV) и подпись `signtool` после сборки
  (установщика и `TKBK IDE.exe` внутри него; VSCodium-овские DLL остаются как есть).
- **macOS.** Бандл подписан ad-hoc (`codesign --sign -`). Для запуска без «приложение повреждено»
  нужны Apple Developer ID, подпись `codesign --deep --options runtime` и нотаризация
  (`notarytool`). Добавить в workflow секреты и шаг подписи.
- **Linux.** Подпись не нужна; при желании — `.deb`/`.rpm`/AppImage (сейчас только `tar.gz`).

## 2. Релиз TKBK Agent
- CI берёт `.vsix` из **последнего релиза** `tkbk-online/tkbk-agent`. Нужно опубликовать релиз
  с файлом `tkbk-agent-<версия>.vsix` (локальная сборка лежит в `H:\tkbk ide\tkbk-agent-0.1.0.vsix`).
  До этого запускать workflow вручную с параметром `agent_vsix_url` или собирать локально с `--agent-vsix`.

## 3. Аккаунты и сервисы
- GitHub: включить Actions в репозитории `tkbk-online/tkbk-ide`, при первом теге проверить черновик релиза.
- Open VSX: публиковать `tkbk-agent`/`tkbk-theme`/`tkbk-welcome` **не обязательно** — они встроены.
  Если захотите — см. `docs/tkbk/OPEN-VSX.md` в репозитории агента.
- Страница `https://tkbk.online/docs` — на неё ведут кнопки «Документация». Если страницы нет,
  поправить `brand/product.json` → `tkbk.docs`.

## 4. Бренд
- Иконка собирается из `brand/logo.png` (копия `public/icon-512.png` сайта). Если нужна отдельная
  иконка приложения — заменить файл, остальное сгенерируется.
- GUID-ы в `brand/product.json` (`win32x64UserAppId` и др.) сгенерированы для TKBK IDE; менять не надо,
  иначе Windows посчитает следующую версию другой программой.

## 5. Проверить с реальным ключом
- Ввести ключ `cr_…` в панели TKBK Agent, убедиться, что список моделей подтянулся из шлюза и
  запрос проходит. У сборочной сессии ключа не было.
- TKBK Tab (автодополнение) проверен только на локальной заглушке шлюза (оба протокола —
  `/chat/completions` и `/messages`). С реальным ключом проверить: качество подсказок `deepseek-v4-pro`,
  задержку, и что шлюз принимает `stop`/`stop_sequences` и `temperature: 0`. Если Claude-модели на шлюзе
  доступны только через `/messages`, всё уже учтено (`tkbk.completion.model` начинающийся с `claude` →
  Anthropic-протокол).

## 6. Передано сессии TKBK Agent (форк)
- Каталог данных `~/.cline`/`CLINE_DIR` → свой `~/.tkbk`/`TKBK_DIR`; уведомление Cline про телеметрию;
  английские строки панели; экспорт `getApiKey()` из расширения, чтобы TKBK Tab брал ключ агента;
  `capabilities.untrustedWorkspaces` (сейчас агент отключён в недоверенных папках); релиз `.vsix`.

## Известные ограничения (не блокируют)
- Первый запуск **portable**-версии: русский интерфейс включается сразу, если редактор запущен
  из его папки (двойной клик, ярлык). Если запустить `TKBK IDE.exe` из другой текущей папки через
  консоль, первый запуск будет на английском, а второй — уже на русском (VS Code сам перепишет
  кэш языковых пакетов). У установщика такого ограничения нет.
- GitLens при первом запуске может открыть вкладку «Welcome» (его эксперимент по удалённому флагу);
  страница TKBK остаётся активной.
- TKBK Agent при первом запуске показывает уведомление Cline про телеметрию и подхватывает данные из
  `~/.cline`, если на машине уже стоял Cline, — это поведение форка (репозиторий `tkbk-agent`), не IDE.
